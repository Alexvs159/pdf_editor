# AGENTS.md — pdf_editor

## Проект

Простой редактор PDF с GUI (PyQt6 + PyMuPDF). Без OCR. Левая панель —
миниатюры страниц, в центре страница с рамками текстовых блоков, справа —
редактор выбранного блока. Язык интерфейса — русский.

## Стек

- Python 3.14, venv в `.venv/`
- PyMuPDF 2.0 (`pymupdf`) — рендер, блоки текста, redaction, шрифты
- PyQt6 6.11 — GUI
- Зависимости: `requirements.txt`

## Архитектура

Три слоя, без смешивания:

- `document.py` — модель, без GUI и Qt. `PdfDocument`:
  - рендер (`page_pixmap`, `thumbnail_pixmap`), блоки (`blocks` → `TextBlock`),
    правка (`set_text`), сохранение (`save_as`), список встроенных шрифтов
    (`embedded_font_names`).
  - `set_text(idx, block, new_text, font_choice, font_size, insert_rect)` —
    единая точка правки блока: redaction старого текста, выбор шрифта,
    вставка (textbox или htmlbox), размер, позиция.
  - `_insert_fit` — вставка с уменьшением размера до 4pt; если не влезло —
    ничего не вставляет, fallback решает вызывающий код.
  - `_first_span_bbox` — измерение фактического bbox после вставки (для
    самокоррекции htmlbox).
  - Вся логика шрифтов и redaction — здесь.
- `window.py` — главное окно PyQt6: миниатюры слева, `QGraphicsView` с
  рамками блоков по центру (блоки выделяются и перетаскиваются мышью),
  справа — текст блока, выбор шрифта (QComboBox), размер шрифта
  (QDoubleSpinBox), Применить/Отменить. Только отображение и ввод;
  бизнес-логика делегируется `PdfDocument`.
- `main.py` — точка входа: `python main.py [файл.pdf]`.

Соглашения:

- GUI не знает про PyMuPDF напрямую, кроме конвертации pixmap → QImage
  (`pixmap_to_qimage`). Всё остальное — через `PdfDocument`.
- Новые возможности сначала добавляются в модель, затем в GUI.
- GUI-смоки гоняются с `QT_QPA_PLATFORM=offscreen`.

## Шрифты (стратегия)

При правке блока, по приоритету:

1. Встроенный шрифт оригинального блока (`extract_font` + `insert_font(fontbuffer=...)`) — сохраняет гарнитуру, включая кириллицу. При неудаче (субсет без глифов) — дальше по цепочке.
2. Явно выбранный пользователем шрифт из списка (встроенный документа или Base-14/CJK). Не-ASCII (кроме CJK) с Base-14 → htmlbox (иначе `?`).
3. Авто: ASCII — похожий Base-14 (по bold/italic/serif/mono имени шрифта); CJK — reserved name (`china-s`, `japan`, `korea`); кириллица/греческий — `insert_htmlbox` (Story, unicode гарантирован, но гарнитура меняется).

Критичные детали, найденные через баги (не ломать):

- **Только короткие зарезервированные имена Base-14** (`helv`, `tibo`, `hebo`…).
  MuPDF считает метрики длинного имени (`helvetica`) с завышенной шириной →
  ложный дефицит места → вечная усадка текста при повторных правках.
- **Запас бокса вставки только вправо/вниз** (`target + (0, 0, 6, 6)`): глифы
  стартуют от origin бокса; после `apply_redactions` MuPDF пересоздаёт ресурс
  шрифта с большей метрикой. Запас влево/вверх дал бы дрейф блока.
- **Самокоррекция htmlbox**: Story кладёт глифы со своим внутренним отступом
  (зависит от шрифта/размера). После вставки измеряется фактический bbox
  первого спана; при отклонении >0.25pt текст перставляется со сдвигом.
  Без этого блок «уползает» на +1/-2.6pt за каждую правку.
- Повторная правка тем же текстом не должна менять размер и позицию —
  это контракт, покрыт `test_no_shrink_and_move`.

Известное ограничение: встроенные шрифты-субсеты могут не содержать глифов
для новых символов (tofu). Отмечать в коде как `shortcut:` при необходимости.

## Ponytail

В проекте активен режим ponytail (level `full`) — «ленивый старший разработчик»:
минимальное изменение, решающее задачу целиком, без лишних абстракций,
опций и «на будущее». Правила:

- Сначала читать код, который затрагивает изменение; учитывать всех
  вызывающих, тесты, фикстуры, конфиги.
- Баг-фикс: grep всех вызывающих функции, затем чинить корень в общем коде.
- Удаление лучше добавления. Не добавлять зависимость ради пары строк.
- Новая нетривиальная логика — один маленький тест или assert-самопроверка.
- Известное ограничение с границей — комментарий вида
  `shortcut: <ограничение>, <когда апгрейдить>`.
- Никогда не резать: валидацию на границах доверия, обработку ошибок,
  предотвращающую потерю данных, безопасность, доступность, то, что явно
  просил пользователь.

Уровни: `lite` / `full` (по умолчанию) / `ultra`. Переключение:
`/ponytail lite|full|ultra`. Выход: «stop ponytail» / «normal mode».

Отчёт об экономии: `/ponytail-gain`. Аудит репозитория: `/ponytail-audit`.
Долговые комментарии: `/ponytail-debt`.

- `test_document.py` — self-check модели без GUI: блоки, roundtrip-правка,
  сохранение в тот же файл, маппинг шрифтов (короткие Base-14 имена),
  стабильность размера/позиции при повторных правках и при перемещении
  (`test_no_shrink_and_move`). Запуск: `.venv/bin/python test_document.py`.
- GUI-смоки — с `QT_QPA_PLATFORM=offscreen` (открытие файла, правка, undo,

- Любая новая нетривиальная логика в модели сопровождается проверкой в
  `test_document.py`.

## Известные ограничения

- Undo хранит снимки всего документа в памяти (до 20 шагов).
- Redo нет.
- Встроенные шрифты-субсеты могут не иметь глифов для новых символов (tofu);
  тогда срабатывает fallback — гарнитура меняется, текст и размер сохраняются.
- `insert_htmlbox` при нехватке места масштабирует текст вниз
  (`scale_low=0` после неудачи с `scale_low=1`) — запрошенный размер
  может не достигаться, если блок мал.
- Redaction выполняется до вставки: сбой вставки оставляет блок пустым
  в памяти (GUI восстанавливает через undo-снимок).
- GUI проверялся offscreen-смоками, живой экран не смотрели.
- Один стиль на блок (шрифт/размер/цвет из первого спана): смешанное
  форматирование внутри блока при правке упрощается.

## История фиксов (кратко, чтобы не наступить снова)

- `get_fonts(full=True)` в pymupdf 2.0 возвращает 7-кортеж — распаковывать `row[:6]`.
- Кириллица/греческий в Base-14 `insert_textbox` дают `?` даже с
  `TEXT_ENCODING_CYRILLIC` — только htmlbox или встроенный TTF-буфер.
- Удаление undo-снимка при ошибке правки = потеря данных; снимок оставлять.
- «Шрифт менялся при сохранении, размер уменьшался при каждой правке» —
  причины и решение в разделе «Шрифты».
