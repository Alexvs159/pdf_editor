# AGENTS.md — pdf_editor

## Проект

Простой редактор PDF с GUI (PyQt6 + PyMuPDF). OCR — через внешний
vision-LLM API (OpenAI-совместимый). Левая панель — миниатюры страниц,
в центре страница с рамками текстовых блоков, справа — редактор выбранного
блока. Язык интерфейса — русский.

## Стек

- Python 3.14, venv в `.venv/`
- PyMuPDF 2.0 (`pymupdf`) — рендер, блоки текста, redaction, шрифты
- PyQt6 6.11 — GUI
- numpy — детекция строк/абзацев OCR по растру
- Зависимости: `requirements.txt`

## Архитектура

Три слоя, без смешивания:

- `document.py` — модель, без GUI и Qt. `PdfDocument`:
  - рендер (`page_pixmap`, `thumbnail_pixmap`), блоки (`blocks` → `TextBlock`),
    правка (`set_text`), сохранение (`save_as`), список встроенных шрифтов
    (`embedded_font_names`).
  - `blocks` режет блоки таблицы по ячейкам (`_table_cells` через
    `find_tables(use_layout=False)` — без гейта layout-анализа, тот
    пропускает реальные таблицы): строка относится к ячейке по центру её
    bbox; разбиваем только если ВСЕ строки блока попали в ячейки и их
    больше одной — обычный текст не режется и не теряется.
  - `TextBlock.line_runs` — ЕДИНСТВЕННЫЙ источник стиля: спаны по строкам
    (`[[{font,size,color,origin,text}]]`), включая смешение начертаний и
    размеров ВНУТРИ строки. `_map_runs` раскладывает новый текст по стилям
    посимвольно через `difflib.SequenceMatcher`: совпавшие символы берут стиль
    исходного, вставленные — стиль предыдущего; соседние одинаковые
    склеиваются в прогон.
  - `TextBlock.line_styles` — вычисляемое свойство (первый спан строки),
    НЕ хранится отдельно: два источника стиля расходились.
  - `TextBlock.invisible` — все спаны блока невидимы (render_mode 3: ни
    filled, ни stroked — `char_flags & 0b11000 == 0`); типично текстовый
    слой OCR поверх растра.
  - `save_as` — в тот же файл инкрементально; если инкремент невозможен
    (после undo документ открыт из памяти) — полная запись. Обновляет
    `self.path`, иначе следующий диалог сохранения предлагает старый файл.
  - `set_text(idx, block, new_text, font_choice, font_size, insert_rect)` —
    единая точка правки блока: redaction, выбор шрифта, построчная вставка.
    Для `block.invisible` красакт дополнительно очищает пиксели изображений
    под блоком (`PDF_REDACT_IMAGE_PIXELS`, fill=белый) — растровый текст
    задвоения не даёт.
    `font_choice`/`font_size` — override на весь блок; `None`/`auto` —
    наследование построчных стилей.
  - `_insert_text_fit` — одна строка `insert_text` от baseline, БЕЗ переноса
    по ширине; усадка только если baseline ушла за низ страницы.
  - `_story_inset` — измеренный (с кэшем) внутренний отступ Story для
    htmlbox-пути: попадание в baseline с первого раза без redact-перестановки.
  - `_page_font_buffers` — снимок буферов встроенных шрифтов ДО redaction.
  - `apply_ocr(idx, blocks, font_path)` — невидимый текстовый слой OCR:
    `insert_text(render_mode=3)` построчно (redaction НЕ нужен), baseline из
    rect'ов строк детекции, иначе равномерно по bbox абзаца. Шрифт: ASCII —
    Base-14 по начертанию (`OcrBlock.style`: bold/italic/serif/mono →
    `hebo`/`tiit`/…); кириллица/греческий — буфер системного TTF
    (`PDF_OCR_FONT` → DejaVu/Liberation/Noto, кэш; начертание не
    применяется); CJK — reserved имена. htmlbox здесь недопустим: он
    вставляется видимым. `OcrBlock` — rect/размер/строки/текст/style.
  - Вся логика шрифтов и redaction — здесь.
- `window.py` — главное окно PyQt6: миниатюры слева, `QGraphicsView` с
  рамками блоков по центру (`BlockItem`: выделение, перетаскивание,
  двойной клик), **in-place** редактор `QGraphicsTextItem` поверх страницы,
  верхняя панель (шрифт, размер + чекбокс «Авто», Применить/Отмена/Undo).
  Боковой панели нет. Только отображение и ввод; бизнес-логика
  делегируется `PdfDocument`.
  - Панель видна ВСЕГДА (`set_block_controls_enabled`): без выбранного блока
    её поля и Применить/Отмена отключены. Скрывать/показывать панель нельзя —
    страница прыгает вниз на её высоту.
  - `scene_rect` — rect рамки в координатах PDF; `_submit` — единая точка
    применения (undo-снимок → `set_text` → перерисовка страницы).
  - `_snapshot` — undo-снимок: не больше 20 шагов и 64 МБ суммарно.
  - `_dirty` — «есть несохранённые правки»; ставится в `_submit`/`undo`,
    снимается после успешного сохранения. `closeEvent` спрашивает только
    по нему (иначе предупреждение после каждого Ctrl+S).
  - `apply_edit` — применение текста из редактора и/или шрифта с размером;
    работает и БЕЗ открытого редактора (перестиль выбранного блока) —
    берёт `block.text` и правит блок `overlay_idx`.
  - `commit_move` — перемещение рамки мышью фиксируется СРАЗУ по отпусканию
    (без «Применить»), вызов отложен через `QTimer.singleShot(0)`, потому что
    перерисовка пересоздаёт сцену. Если открыт редактор, набранный текст
    сначала применяется (ищется блок по прежней позиции), а не выбрасывается.
  - `prompt_save` — сохранение под `try/except` + диалог ошибки: исключение
    в слоте Qt роняет приложение вместе с несохранёнными правками.
  - `copy_block_text` — текст блока (в т.ч. ячейки таблицы) в буфер обмена;
    вызывается из контекстного меню рамки (`BlockItem.contextMenuEvent`:
    Копировать / Вырезать / Удалить) и по `Ctrl+C` на выделенном блоке
    (`_copy_selected`; хоткей выключен, пока открыт in-place редактор —
    иначе «съедает» копирование выделения внутри оверлея; вкл/вкл в
    `start_edit`/`cancel_edit`/`_submit`; создаётся ВКЛЮЧЁННЫМ, иначе
    Ctrl+C не работал до первого открытия редактора). `cut_block_text` — копировать + удалить;
    `delete_block_text` — удаление текста блока через `_submit(b, "")`
    (undo работает, для невидимого слоя растр тоже затирается).
  - `print_pages` — печать через системный диалог: ввод страниц
    (`parse_page_ranges`: "1,3,5-7" или пусто = весь документ), затем
    `QPrintDialog`. `print_pages_to` — рендер модели постранично
    (`page_pixmap` zoom=2.5) как изображение, вписанное в страницу принтера
    (painter.setWindow в пунктах). Текст при печати не извлекается — это
    растер.
  - OCR: меню `OCR` (страница / весь документ / настройки), `OcrWorker(QThread)`
    и контроллер `run_ocr`. `load_ocr_config` — env-дефолты, перекрытые
    QSettings. Воркер получает готовые растры страниц (pixmap), вставляет
    результат только ЦЕЛИКОМ после успеха всех страниц; undo-снимок ДО
    вставки; при сбое вставки — `undo()` (откат). Повёрнутые страницы
    пропускаются, страницы с текстом — confirm-диалог. Действия OCR на время
    работы disabled, курсор busy.
- `ocr.py` — OCR-пайплайн слоя модели, без Qt:
  - `detect_text_blocks` — геометрия по растру (numpy): бинаризация `<128`,
    строковый профиль `[2, 0.6*w]` (сплошные ряды — линейки, отбрасываются),
    колоночный профиль, склейка строк в абзацы (зазор `< 0.8*высота`,
    горизонтальное перекрытие `>= 50%`). Координаты — сразу в PDF-пунктах.
  - `OcrClient` — OpenAI-совместимый `/chat/completions` (stdlib urllib),
    base64-PNG кропа, `temperature=0`; ответ — JSON `{text, bold, italic,
    serif, mono}` (`_parse_reply`); не-JSON ответ = просто текст, стиль
    остаётся эвристике. `_estimate_style` — толщина штриха (bold) и
    наклон центроида (italic) по растру; явные теги LLM перекрывают её.
  - `run_page_ocr` — detection → кропы → параллельные вызовы
    (`ThreadPoolExecutor`, один ретрай на кроп). LLM видит только кроп и
    НЕ отдаёт координаты: boxes всегда от детекции.
  - `OcrConfig`/`config_from_env` — `PDF_OCR_BASE_URL`, `PDF_OCR_MODEL`,
    `PDF_OCR_API_KEY`, `PDF_OCR_FONT`.
- `main.py` — точка входа: `python main.py [файл.pdf]`.

Соглашения:

- GUI не знает про PyMuPDF напрямую, кроме конвертации pixmap → QImage
  (`pixmap_to_qimage`). Всё остальное — через `PdfDocument`.
- Новые возможности сначала добавляются в модель, затем в GUI.
- GUI-смоки гоняются с `QT_QPA_PLATFORM=offscreen`.

## Шрифты (стратегия)

При правке блока, по приоритету (для каждой строки отдельно):

1. Встроенный шрифт оригинального блока (`extract_font` + `insert_font(fontbuffer=...)`) — сохраняет гарнитуру, включая кириллицу. При неудаче (субсет без глифов) — дальше по цепочке.
2. Явно выбранный пользователем шрифт из списка (встроенный документа или Base-14/CJK). Не-ASCII (кроме CJK) с Base-14 → htmlbox (иначе `?`).
3. Авто: ASCII — похожий Base-14 (по bold/italic/serif/mono имени шрифта); CJK — reserved name (`china-s`, `japan`, `korea`); кириллица/греческий — `insert_htmlbox` (Story, unicode гарантирован, но гарнитура меняется).

Критичные детали, найденные через баги (не ломать):

- **Только короткие зарезервированные имена Base-14** (`helv`, `tibo`, `hebo`…).
  MuPDF считает метрики длинного имени (`helvetica`) с завышенной шириной →
  ложный дефицит места → вечная усадка текста при повторных правках.
- **Вставка построчная `insert_text` от baseline, без бокса.** `insert_textbox`
  переносит текст по ширине бокса → «блок растёт на строку» без просьбы
  пользователя. Перенос == только явный `\n` во входном тексте.
- **Блок растёт вправо, а не переносится.** Бокс htmlbox нельзя обрезать
  `page.rect.x1`: при нехватке места Story усаживает строку (`scale_low`).
  Бокс расширяется за край страницы с повтором, усадка — последний рубеж.
  В GUI оверлей правки создаётся с `setTextWidth(-1)` (без переноса),
  подложка растёт за текстом (`_fit_overlay_bg`).
- **Позиции строк — исходные baseline (`origin`)**, а не пересчёт от bbox.
  При совпадении числа строк координаты не меняются вовсе; иначе укладка
  от первой baseline шагом `size*1.2`. Иначе блок дрейфует при правках.
- **htmlbox-путь**: Story кладёт глифы со своим внутренним отступом, который
  зависит только от размера (измеряется `_story_inset`, кэш). Вход в baseline
  вычитанием отступа. Redact-перестановка (как было раньше) НЕДОПУСТИМА:
  MuPDF удаляет весь текст, чей bbox пересекает красакт, — пропадали соседние
  строки.
- **Буферы шрифтов — снимок ДО redaction** (`_page_font_buffers`): MuPDF
  удаляет ресурс шрифта, если красактом вырезан весь его текст.
- **Пробел из TTF-буфера извлекается как `\xa0`** — `blocks()` нормализует
  в обычный пробел, иначе `\xa0` уходит в редактор и в следующие вставки.
- Повторная правка тем же текстом не должна менять размер, стиль и позицию —
  контракт, покрыт `test_no_shrink_and_move`, `test_no_wrap_longer_text`,
  `test_line_styles_per_line`.
- Смешение начертаний внутри строки держится на `line_runs` + сопоставлении
  начертания при выборе буфера шрифта: имя спана `CharisSIL` — префикс
  `/BaseFont` `Charis SIL Bold`, без проверки bold/italic обычный прогон
  получал жирный буфер и «весь текст становился жирным».

Известное ограничение: встроенные шрифты-субсеты могут не содержать глифов
для новых символов (tofu). Отмечать в коде как `shortcut:` при необходимости.

## Ponytail

В проекте активен режим ponytail (level `full`) — «ленивый старший разработчик»:
минимальное изменение, решающее задачу целиком, без лишних абстракций,
опций и «на будущее». Правила:

- Сначала читать код, который затрагивает изменение; учитывать всех
  вызывающих, тесты, фикстуры, конфиги.
- Баг-фикс: grep всех вызывающих функции, затем чинить корень в общем коде.
- Удаление лучше добавления. Не добавлять зависимость ради пары строк.
- Новая нетривиальная логика — один маленький тест или assert-самопроверка.
- Известное ограничение с границей — комментарий вида
  `shortcut: <ограничение>, <когда апгрейдить>`.
- Никогда не резать: валидацию на границах доверия, обработку ошибок,
  предотвращающую потерю данных, безопасность, доступность, то, что явно
  просил пользователь.

Уровни: `lite` / `full` (по умолчанию) / `ultra`. Переключение:
`/ponytail lite|full|ultra`. Выход: «stop ponytail» / «normal mode».

Отчёт об экономии: `/ponytail-gain`. Аудит репозитория: `/ponytail-audit`.
Долговые комментарии: `/ponytail-debt`.

## Известные ограничения

- Undo хранит снимки всего документа в памяти: до 20 шагов и 64 МБ суммарно
  (старые выбрасываются первыми).
- Redo нет.
- Встроенные шрифты-субсеты могут не иметь глифов для новых символов (tofu);
  тогда срабатывает fallback — гарнитура меняется, текст и размер сохраняются.
- `insert_htmlbox` при нехватке места масштабирует текст вниз
  (`scale_low=0` после неудачи с `scale_low=1`) — запрошенный размер
  может не достигаться, если строка не влезает у нижнего края страницы.
- Redaction выполняется до вставки: сбой вставки оставляет блок пустым
  в памяти (GUI восстанавливает через undo-снимок).
- GUI проверялся offscreen-смоками, живой экран не смотрели.
- Стиль фиксируется **поспаново** (`line_runs`); границы прогонов при правке
  определяются посимвольным сопоставлением (difflib), поэтому стиль может
  «съехать» на символ при неоднозначной замене.
- Позиции прогонов после изменённого текста считаются по метрикам шрифта:
  на субсетах возможно расхождение с раскладкой продюсера ~0.3pt на прогон
  (неизменённый текст берёт исходные `origin` — там drift = 0).
- Длинная строка не переносится: на `insert_text`-пути уходит за правый край
  страницы, на htmlbox-пути расширяется до края и обрезается там
  (намеренно — перенос только по явному `Enter`).
- Шрифт in-place оверлея приблизительный (QFont по имени, встроенный TTF
  в Qt не загружается); точную гарнитуру применяет модель при вставке.
  Кегль оверлея = кегль блока (`setPixelSize(round(size))`: 1px = 1 пункт
  страницы при любом zoom и DPI).
- Вставка встроенным субсетом перекодирует дефис `-` в мягкий перенос
  `\xad`: текст на странице выглядит верно, но `blocks()` вернёт его с `\xad`
  (артефакт MuPDF, был и раньше; `\xa0` нормализуется, `\xad` — нет).
- OCR: правка блока невидимого слоя (`block.invisible` — все спаны без
  filled/stroked, `char_flags & 0b11000 == 0`) затирает растр под блоком
  через redaction с `PDF_REDACT_IMAGE_PIXELS` (fill=белый). Блок со
  смешанными видимыми/невидимыми спанами считается обычным — смешанный
  случай растр не очищает (shortcut, редко встречается).
- OCR: детекция только тёмное-на-светлом и без deskew — инверсные/перекошенные
  (> ~3°) сканы ломают профили; крупные рисунки могут приниматься за текст.
- OCR: начертание (bold/italic/serif/mono) применяется только к ASCII-тексту;
  кириллица вставляется единым системным TTF. Эвристика bold может ложно
  срабатывать на сплошных плашках/логотипах (широкие штрихи).
- OCR: невидимый слой не умеет htmlbox → не-ASCII скрипты кроме
  кириллицы/греческого/CJK дают `ValueError` (нужен TTF через `PDF_OCR_FONT`).
- OCR: повёрнутые страницы (`page.rotation != 0`) пропускаются с
  предупреждением; ключ API хранится в QSettings в открытом виде.
- HTTP-клиент OCR — stdlib urllib; таймаут 60с на кроп, один ретрай.

## История фиксов (кратко, чтобы не наступить снова)

- `get_fonts(full=True)` в pymupdf 2.0 возвращает 7-кортеж — распаковывать `row[:6]`.
- Кириллица/греческий в Base-14 `insert_textbox` дают `?` даже с
  `TEXT_ENCODING_CYRILLIC` — только htmlbox или встроенный TTF-буфер.
- Удаление undo-снимка при ошибке правки = потеря данных; снимок оставлять.
- «Шрифт менялся при сохранении, размер уменьшался при каждой правке» —
  причины и решение в разделе «Шрифты».
- «Строка переносится сама, блок растёт на строку» — `insert_textbox`
  переносит по ширине бокса; лечится построчным `insert_text` от baseline
  (см. «Шрифты»). Перенос — только по явному `\n`.
- In-place оверлей в GUI не должен быть источником истины о стиле:
  он лишь показывает текст, стиль берётся из `line_runs` модели.
- **Комбобокс шрифта всегда стартует с «Авто».** Подставлять туда шрифт
  первого спана нельзя: это override на весь блок, и блок со смешанными
  начертаниями («Поставщик: …» жирный, адрес и телефон обычные) становился
  целиком жирным. Покрыто смоком 9 в `test_gui_edit.py`.
- «Весь текст в блоке стал жирным» — стиль брался с первого спана строки;
  лечится `line_runs` + посимвольным сопоставлением и проверкой начертания
  при префиксном подборе буфера шрифта.
- «Текст переносится на новую строку сам» — `setTextWidth(rect.width())`
  у оверлея и бокс htmlbox, обрезанный краем страницы. Перенос — только `\n`.
- «Сохранение уронило приложение» — исключение в слоте Qt (нет `try/except`
  вокруг `save_as`) даёт SIGABRT и теряет несохранённые правки.
- «После Ctrl+Z нельзя сохранить в исходный файл» — инкрементальная запись
  требует исходный файл; после undo документ из памяти → полная запись.
- «Перетащил блок — пропал набранный текст» — `commit_move` вызывал
  `cancel_edit`; теперь сначала применяет открытую правку.
- pymupdf 2.0: у `Page.insert_text` НЕТ параметра `fontbuffer` — сначала
  `page.insert_font(fontname=..., fontbuffer=...)`, затем `insert_text(fontname=ref)`.
  `Pixmap(cs, w, h, samples, alpha)` — аргументы позиционные (kwargs не принимает).
- PyQt6: у `QGraphicsSceneContextMenuEvent` НЕТ `globalPos()` — меню
  блока роняло приложение (SIGABRT из Qt-слота); использовать
  `event.screenPos()`.
- Невидимый текст: `insert_text(render_mode=3)`; проверка в тесте —
  `b"3 Tr" in page.read_contents()`. htmlbox невидимым не бывает.
- «Текст на скане не копируется после OCR» — кириллица в Base-14 не
  кодируется, нужен буфер системного TTF (`PDF_OCR_FONT` → DejaVu/Liberation/
  Noto); на этой машине DejaVu лежит в `/usr/share/fonts/TTF`, регулярный
  кириллический — `Noto/NotoSans-Regular.ttf`.
